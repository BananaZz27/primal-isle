# เอกสารออกแบบ: เกมเอาชีวิตรอดออนไลน์ "Primal Isle — เกาะดึกดำบรรพ์" (ชื่อชั่วคราว)

วันที่: 2026-11-21 · ผู้สร้าง: Claude (โบ๊ทให้ Claude ทำเองทั้งหมด)

---

## 1. เป้าหมายและเหตุผล (Intent)

- เกมเอาชีวิตรอดมุมมองจากด้านบน (top-down) แนวเดียวกับ Durango: Wild Lands คือ เก็บทรัพยากร → คราฟต์ของ → สร้างฐาน → ล่าและเทมสัตว์ (taming = ทำให้สัตว์เชื่องแล้วกลายเป็นพวกเรา)
- **เล่นได้ทุกที่ทุกแพลตฟอร์ม** ทั้งมือถือ แท็บเล็ต และคอม ผ่านเบราว์เซอร์ ไม่ต้องติดตั้งแอป
- **ออนไลน์เล่นกับเพื่อน** ในโลกเดียวกัน แค่ส่งลิงก์ให้เพื่อนก็เข้ามาเล่นได้
- เริ่มเล็กที่ระดับกลุ่มเพื่อนก่อน แล้วค่อยขยาย
- ภาพแบบ pixel art ใช้ asset โอเพนซอสที่ใบอนุญาตเปิดให้ใช้ได้

## 2. เป้าหมาย / สิ่งที่ไม่ทำ / สิ่งที่ถือว่าล้มเหลว

**เป้าหมาย (Goals)**
- เปิดลิงก์บนมือถือแล้วเล่นได้ภายในไม่กี่วินาที และลื่นบน Android รุ่นกลาง
- เพื่อนสูงสุด 8 คนอยู่ในโลก (world/room) เดียวกัน เห็นกันแบบ real-time
- โลกถูกบันทึก (save) ไว้ ออกแล้วกลับเข้ามา ฐานที่สร้างไว้ยังอยู่
- โค้ดแยกหน้าที่ชัดเจน ให้คนอื่นมาอ่านและแก้ต่อได้ง่าย

**สิ่งที่ไม่ทำในรุ่นแรก (Non-goals)**
- ไม่ทำ 3D ไม่ทำ MMO ขนาดใหญ่ ไม่ลง App Store/Play Store (เพิ่มทีหลังได้)
- ไม่มีระบบสมัครสมาชิกด้วยรหัสผ่าน ใช้ชื่อเล่น + รหัสห้องแทน
- ไม่มีระบบเติมเงินหรือโฆษณา

**สิ่งที่ถือว่าล้มเหลวแม้จะใช้งานได้ (Anti-goals)**
- กระตุกหรือหน่วงจนเล่นบนมือถือไม่สนุก
- เพื่อนเข้าเล่นยาก เช่น ต้องลงโปรแกรม ต้องสมัครสมาชิก หรือต้องตั้งค่าเครือข่าย
- โค้ดกองรวมอยู่ในไฟล์ใหญ่ไม่กี่ไฟล์จนแก้ต่อไม่ได้
- ใช้ asset ที่ license ห้ามใช้เชิงพาณิชย์ (NC) เพราะอนาคตอาจอยากหารายได้จากเกม

## 3. ข้อจำกัด (Constraints)

- โบ๊ทมีเวลาประมาณ 1–4 ชั่วโมงต่อวัน งานจึงต้องแบ่งเป็นขั้นที่จบในตัว และทุกขั้นต้องเล่นได้จริง
- โบ๊ทถนัด Python และ C/C++ ส่วน TypeScript ยังใหม่ โค้ดจึงต้องอ่านง่าย มีคอมเมนต์อธิบายภาษาไทยในจุดสำคัญ
- เครื่องที่ Claude ใช้สร้างดาวน์โหลดได้เฉพาะจาก **GitHub และ npm** (itch.io, OpenGameArt, kenney.nl เข้าไม่ได้) asset จึงต้องมาจาก repo บน GitHub หรือ Claude วาดเอง
- โฮสต์ (ที่ตั้งเซิร์ฟเวอร์) ต้องฟรีหรือเกือบฟรี
- ห้ามใส่ API key หรือรหัสลับใดๆ ลงใน repo

## 4. ทางเลือกที่พิจารณา (Approaches)

| ทางเลือก | ข้อดี | ข้อเสีย | ผล |

| **A) Phaser 4 + Colyseus 0.18 (TypeScript ทั้งระบบ)** | เบา รันบนเว็บมือถือได้ดี ฝั่งเกมกับเซิร์ฟเวอร์ใช้ภาษาเดียวกัน จึงแชร์โค้ดกติกาเกมได้ Colyseus 0.18 มี client prediction และ interpolation ในตัว | ต้องเรียน TypeScript และต้องมีเซิร์ฟเวอร์ที่รันตลอดเวลา | **เลือก** |

(โบ๊ทเลือก A ตามคำแนะนำ และให้ Claude ตัดสินใจเรื่องวิธีสร้างทั้งหมด)

## 5. การตัดสินใจหลัก

### 5.1 ธีม — *โบ๊ทเลือก: แบบเดียวกับ Durango*
**คนยุคปัจจุบันหลุดมาติดเกาะยุคไดโนเสาร์** ต้องเริ่มจากมือเปล่า แล้วค่อยๆ ไต่ระดับเทคโนโลยี
- **สภาพแวดล้อม:** ป่าดิบ ทุ่งหญ้า ชายหาด แม่น้ำ และภูเขาไฟ (ไบโอมเพิ่มทีหลัง)
- **สัตว์:** ไดโนเสาร์ตัวเล็กกินพืชไว้ล่า เช่น ไดโนตัวจิ๋ว ไดโนปากเป็ด ไดโนเสาร์กินเนื้อขนาดกลางที่ล่าเป็นฝูง เช่น แร็พเตอร์ ไดโนใหญ่ที่ทำร้ายเราเฉพาะตอนโดนยั่ว เช่น ไทรเซอราทอปส์ และสัตว์บินอย่างเทอโรซอร์
- **เทม:** ไดโนเสาร์บางชนิดเทมได้ ให้เดินตามช่วยสู้ และในอนาคตจะขี่หรือใช้ขนของได้
- **กลิ่นอายยุคปัจจุบัน:** มีลังเสบียงจากโลกปัจจุบันโผล่มาเป็นครั้งคราว ข้างในมีของหายาก เช่น ผ้าพันแผล มีด หรือเศษโลหะ
- **ลิขสิทธิ์:** ยึดแนวเกมและบรรยากาศแบบเดียวกัน แต่ทุกอย่างต้องเป็นของเราเอง ห้ามใช้ชื่อ โลโก้ ตัวละคร ภาพ หรือเสียงจาก Durango และห้ามตั้งชื่อเกมให้คล้าย
- ถ้าหาภาพไดโนเสาร์ CC0/CC-BY บน GitHub ไม่ได้ Claude จะวาด pixel art เอง

### 5.2 สถาปัตยกรรม (โครงสร้างโค้ด)
ใช้ **monorepo** คือ repo เดียวที่แบ่งเป็น 3 แพ็กเกจ ใช้ npm workspaces:

```
primal-isle/
├─ shared/     กติกาเกมล้วนๆ ไม่ขึ้นกับหน้าจอหรือเครือข่าย
│   ├─ data/   items.json, recipes.json, creatures.json, buildings.json
│   ├─ world/  สร้างแผนที่จาก seed (procedural generation)
│   └─ rules/  ฟังก์ชันคำนวณ: คราฟต์, ความหิว, ความเสียหาย, การเทม
├─ server/     Colyseus: ห้องเกม, ตรวจสอบคำสั่ง, AI สัตว์, บันทึกโลก
└─ client/     Phaser 4: วาดภาพ, รับ input, UI, ส่วนเชื่อมเครือข่าย
    ├─ scenes/    Boot, Menu, World, UI
    ├─ render/    วาด sprite/tilemap จาก state
    ├─ input/     keyboard + joystick สำหรับจอสัมผัส
    ├─ net/       เชื่อม Colyseus (แยกจากส่วนวาดภาพ)
    └─ ui/        กระเป๋า, หน้าคราฟต์, แถบเลือด/หิว/น้ำ
```

- **Server authoritative** หมายถึงเซิร์ฟเวอร์เป็นผู้ตัดสินความจริง ฝั่งผู้เล่นส่งแค่ "ความตั้งใจ" (เช่น เดินไปทางขวา หรือตีต้นไม้ต้นนี้) แล้วเซิร์ฟเวอร์เป็นคนตรวจสอบและคำนวณผล วิธีนี้กันโกงพื้นฐาน และทำให้ทุกคนเห็นโลกตรงกัน
- **แผนที่สร้างจาก seed** (ตัวเลขตั้งต้นของการสุ่ม) ทั้งฝั่งเซิร์ฟเวอร์และฝั่งผู้เล่นสร้างแผนที่ฐานเหมือนกันจาก seed เดียวกัน จากนั้นซิงก์เฉพาะ "สิ่งที่เปลี่ยน" เช่น ต้นไม้ที่ถูกตัดหรือกำแพงที่สร้าง จึงประหยัดเน็ตมาก
- **Data-driven** หมายถึงไอเทม สูตรคราฟต์ และสัตว์อยู่ในไฟล์ JSON ถ้าจะเพิ่มของใหม่ก็แก้ข้อมูล ไม่ต้องแก้โค้ด
- เซิร์ฟเวอร์อัปเดตโลก (tick) 20 ครั้งต่อวินาที ฝั่งผู้เล่นทำ interpolation (เกลี่ยตำแหน่งให้ลื่น) และ prediction (ขยับตัวเราทันทีโดยไม่รอเซิร์ฟเวอร์)

### 5.3 การเข้าเล่น
- หน้าแรกให้ใส่ชื่อเล่น แล้วเลือก "สร้างโลกใหม่" หรือ "เข้าโลกด้วยรหัส"
- ลิงก์เชิญจะมีรหัสห้องในตัว เพื่อนกดแล้วเข้าได้ทันที
- ผู้เล่นจำตัวตนด้วย token ที่เก็บในเบราว์เซอร์ จึงกลับเข้ามาเป็นตัวเดิมได้ ไม่ต้องใช้รหัสผ่าน
- ทำเป็น **PWA** (เว็บที่เพิ่มเป็นไอคอนบนหน้าจอโฮมได้ และเปิดเต็มจอเหมือนแอป)

### 5.4 การควบคุม
- มือถือ: joystick เสมือนฝั่งซ้าย ปุ่มโต้ตอบ (ตี/เก็บ/ใช้) ฝั่งขวา และแตะไอคอนเพื่อเปิดกระเป๋า
- คอม: WASD สำหรับเดิน คลิกเมาส์เพื่อโต้ตอบ E เปิดกระเป๋า
- ล็อกจอแนวนอนบนมือถือ

### 5.5 ระบบเกมรุ่นแรก
- **ค่าสถานะ:** เลือด ความหิว น้ำ ถ้าหิวหรือกระหายจนหมด เลือดจะลด
- **เก็บของ:** ต้นไม้ → ไม้, หิน → หิน, พุ่มไม้ → ผลไม้/เส้นใย, แหล่งน้ำ → น้ำ ทรัพยากรงอกใหม่ตามเวลา
- **คราฟต์:** เครื่องมือ (ขวาน อีเต้อ หอก) อาหารปรุงสุก และชิ้นส่วนสิ่งก่อสร้าง
- **สร้างฐาน:** วางตามช่องตาราง (grid) ได้แก่ พื้น กำแพง ประตู กองไฟ กล่องเก็บของ
- **สัตว์:** AI แบบง่าย 3 พฤติกรรม คือ เดินเล่น หนี และโจมตี ล่าแล้วได้เนื้อและหนัง
- **เทม:** ให้อาหารที่สัตว์ชอบจนแถบความเชื่องเต็ม สัตว์จะเดินตามและช่วยสู้
- **ตาย:** เกิดใหม่ที่จุดเกิดหรือที่นอนของตัวเอง และของในกระเป๋าตกไว้ที่จุดตาย
- **PvE เท่านั้น** (เล่นร่วมกันสู้ธรรมชาติ ผู้เล่นตีกันเองไม่ได้) — *Claude ตัดสินใจ* เพราะเป้าหมายคือเล่นกับเพื่อน

### 5.6 ภาพและเสียง (Assets)
- tile ขนาด 16×16 พิกเซล ขยายภาพแบบ pixel-perfect (ไม่เบลอ)
- แหล่งที่มา: repo บน GitHub ที่เป็น **CC0** (ใช้ได้อิสระ) หรือ **CC-BY** (ใช้ได้แต่ต้องให้เครดิต) เท่านั้น ห้าม NC และหลีกเลี่ยง share-alike (เช่น CC-BY-SA, GPL) ในส่วนภาพ ถ้าไม่จำเป็น
- ส่วนที่หาไม่ได้ เช่น ไดโนเสาร์บางชนิด Claude จะวาดเองด้วยสคริปต์ที่แปลง "ตารางสีแบบตัวอักษร" เป็น sprite sheet ซึ่งแก้ไขผ่านโค้ดได้
- ทุกไฟล์ต้องบันทึกที่มาและ license ใน `CREDITS.md`

### 5.7 การบันทึกโลก
- เซิร์ฟเวอร์ใช้ไฟล์ SQLite (ฐานข้อมูลในไฟล์เดียว) เก็บสิ่งที่เปลี่ยนในโลก + กระเป๋าผู้เล่น โดยบันทึกอัตโนมัติทุก 30 วินาทีและตอนห้องปิด
- ห่อการบันทึกไว้หลัง interface (`WorldStore`) เพื่อให้เปลี่ยนไปใช้ฐานข้อมูลอื่นได้ภายหลังโดยไม่ต้องแก้ส่วนอื่น

### 5.8 การโฮสต์
- **ฝั่งเกม (client):** GitHub Pages ฟรี
- **ฝั่งเซิร์ฟเวอร์:** ช่วงพัฒนารันบนคอมของโบ๊ท (HP Victus) ก่อน แล้วค่อยย้ายขึ้นเซิร์ฟเวอร์ฟรีในขั้นที่ 6 ตัวเลือกหลักคือ Oracle Cloud Always Free ซึ่งเปิดตลอดและบันทึกข้อมูลถาวรได้ แต่ต้องสมัครด้วยบัตร ตัวเลือกสำรองคือ Render free ซึ่งหลับเมื่อไม่มีคนใช้ 15 นาทีและไม่มีดิสก์ถาวร — **เรื่องนี้ให้โบ๊ทเลือกตอนถึงขั้นที่ 6**

### 5.9 ขั้นตอนการสร้าง (Milestones)
ทุกขั้นต้องจบด้วยของที่เปิดเล่นได้จริง:

1. **โครงร่าง:** สร้าง monorepo, คำสั่ง dev, ระบบเทสต์ และ GitHub Actions
2. **เดินด้วยกัน:** สร้าง/เข้าห้อง เดินบนแผนที่ที่สร้างจาก seed เห็นเพื่อนขยับลื่น และใช้ joystick บนมือถือได้
3. **เอาชีวิตรอด:** เก็บทรัพยากร กระเป๋า เลือด/หิว/น้ำ กิน และดื่ม
4. **คราฟต์:** หน้าคราฟต์ เครื่องมือที่ทำให้เก็บของเร็วขึ้น และกองไฟสำหรับปรุงอาหาร
5. **สร้างฐาน + บันทึกโลก:** วางสิ่งก่อสร้าง กล่องเก็บของ ที่นอน และ save/load
6. **ไดโนเสาร์ + ออนไลน์จริง:** AI ไดโนเสาร์ 3–4 ชนิด ล่า เทม PWA และ deploy ให้เพื่อนเล่นได้
7. **โลกมีชีวิต:** ลังเสบียงจากโลกปัจจุบัน กลางวัน/กลางคืน ไดโนเพิ่ม และเก็บรายละเอียด (polish)

ส่วนที่ทำทีหลัง: หลายไบโอม (ภูมิประเทศ) การขี่ไดโนเสาร์ เสียงเพลง และแอปมือถือแบบติดตั้ง
